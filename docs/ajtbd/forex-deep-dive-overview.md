## Критическое исправление: модель продукта

Предыдущий анализ строился на **ошибочной** предпосылке, что продукт -- "мультиброкерный агрегатор для розничных трейдеров". Это **неверно**.

### Корректная модель

| Параметр | Значение |
|----------|----------|
| **Тип продукта** | B2B white-label фронтенд (trader room / личный кабинет / client cabinet) |
| **Покупатель (B2B)** | Форекс-брокеры (MaxiMarkets, UMarkets, LimeFX, DowMarkets, ForexBY, GWG, 1Prime и др.) |
| **Конечный пользователь (B2C)** | Розничные трейдеры, клиенты конкретного брокера |
| **Ключевое уточнение** | Трейдер работает с ОДНИМ брокером -- агрегации нескольких брокеров НЕТ |
| **Бэкенд** | xCritical CRM (не разрабатывается в рамках myaccount-front) |
| **Текущий этап** | Рефакторинг JS --> TypeScript/Next.js 16 (CRM-42322) |
| **Существующие фичи** | Deposit, Withdrawal, Personal Data, KYC, Account Status, Documents, Copy Trading, PAMM, Onboarding, Change Password, Promo/Offers, Appropriateness Test, Economic Profile |

### Двухслойная природа продукта

myaccount-front имеет **двух клиентов**, и анализ требует двух слоев Jobs:

```
Слой 1: B2B (Брокер -- покупатель продукта)
   "Мне нужен современный trader room для моих клиентов"
         |
         | покупает/разворачивает
         v
   myaccount-front (white-label)
         |
         | используют
         v
Слой 2: B2C (Трейдер -- конечный пользователь)
   "Мне нужен удобный личный кабинет у моего брокера"
```

**B2C-ценность -- ключевой дифференциатор в B2B-продажах**: если трейдеры довольны кабинетом, брокер получает больше депозитов, меньше оттока, меньше тикетов в поддержку.

## Методология AJTBD

**Advanced Jobs To Be Done** -- расширенная версия JTBD-фреймворка с элементами:

1. **Jobs Graph** -- иерархия работ (Big Job --> Core Job --> Small Jobs --> Micro Jobs)
2. **Desired Outcomes (ODI)** -- измеримые результаты по Ulwick (Importance x Satisfaction = Opportunity Score)
3. **Forces of Progress** -- Push/Pull vs Habit/Anxiety
4. **Segment Profiles** -- глубинные профили сегментов
5. **Value Proposition Canvas** -- соответствие продукта задачам
6. **RAT (Risky Assumptions Test)** -- валидация рискованных допущений

Для двухслойного продукта каждый элемент анализируется **дважды**: для B2B-слоя (брокер) и B2C-слоя (трейдер).

## Executive Summary

### Ключевые выводы

1. **Продукт уже существует и приносит деньги**. Это не стартап-гипотеза -- 10+ брокерских брендов используют текущую версию. Задача -- модернизировать фронтенд для увеличения конкурентоспособности.

2. **Двухслойная ценность = двойной рычаг**. Улучшая B2C-опыт трейдера (удобство, скорость, аналитика), мы одновременно улучшаем B2B-метрики брокера (retention, FTD rate, support costs).

3. **Рынок Forex CRM -- $516-530M** (2025), CAGR 6.5-7.8%. Из 6,500+ брокеров ~72% уже покупают CRM/trader room. Рынок зрелый, но фрагментированный.

4. **Конкурентное преимущество**: современный стек (Next.js 16 / React 19) + проверенный бэкенд (xCritical CRM) + AI-first разработка. Большинство конкурентов работают на legacy-стеках.

5. **Главная B2B-возможность**: ценовой разрыв между бюджетными ($500-1,500/мес) и премиум ($5,000+/мес) решениями. Mid-tier сегмент ($1,500-5,000/мес) наиболее конкурентный и привлекательный.

6. **Главная B2C-возможность**: встроенная аналитика (метрики, визуализации), которую трейдеры сейчас получают через внешние инструменты (MyFXBook, TradesViz).

7. **Критический тренд**: 68% брокеров внедряют AI-powered CRM. AI-фичи из "nice-to-have" превращаются в "must-have".
